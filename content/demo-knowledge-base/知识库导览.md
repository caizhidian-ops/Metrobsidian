# 知识库导览：从桌面资料到一座不太整齐的城市

这座城市不是从一个完美分类法开始的。先有一堆产品草稿、周度复盘、研究报告、训练记录、搬家清单、项目 README；后来才试着问：这些东西之间到底有什么关系？

目前最值得看的不是建筑说明，而是几个真实问题：

- 工作里，"生成一次"为什么不等于"完成一份视觉交付"？
- 学习里，模型越来越强时，应用到底能积累什么？
- 生活里，数据很不完整的训练记录还能告诉我什么？
- 灵感里，一个看起来很有趣的 Agent 想法如何承认自己还没验证？

知识库按「个人知识类型」独立组织（工作/学习/案例/生活/健康/复盘/灵感/创作），与 3D 场景的建筑解耦——建筑只是展示形态，映射关系见 [建筑映射.md](建筑映射.md)。

建议从 [02_学习/商业模式与壁垒](02_学习/商业模式与壁垒_工作草稿.md) 或 [01_工作/从助手到视觉工作台](01_工作/从助手到视觉工作台_阶段草稿.md) 开始。
