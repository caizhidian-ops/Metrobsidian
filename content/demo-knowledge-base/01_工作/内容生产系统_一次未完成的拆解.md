# 内容生产系统：一次未完成的拆解

我曾把内容生产拆成一条很长的链：选题对标 → 文案与图像制作 → 人工修改 → 发布 → 评论与私信 → 数据回收 → 决定下一轮。

那时最直接的反思是：一张单独的封面图，既未必带来分发，也未必让人互动；无关热点更不能因为“热”就硬蹭。内容要么让人有表达欲，要么和产品有真实连接，最好两者都有。

草稿里留下了许多还没搭好的东西：灵感库、素材库、内容状态机、按题材/形式/功能拆的数据看板。真正困难的不是让 AI 产出一段文案，而是让每一轮数据能反过来改变下次选题。

一个仍然有效的工作规则：机器负责把选择空间打开，人负责决定主题、选图片、改文案，并对“这值得发吗”负责。
